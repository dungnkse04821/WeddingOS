7. **finance_summaries read mechanism**:
   - `CREATE VIEW public.finance_summaries WITH (security_invoker = true)`. It relies on RLS applied to `public.weddings` to filter summaries correctly based on the current user context.
   - `api_v1.get_finance_summary` was deleted.

8. **OWNER/COLLABORATOR security boundary**:
   - BudgetItem and Finance entities are strictly RLS-scoped to `is_wedding_owner()` or explicitly verified `is_active_wedding_member()` for read/write.
   - Trusted operations internally enforce member active status.

9. **Payment/Refund direct-CUD restriction**:
   - Standard `authenticated` users are denied `INSERT`, `UPDATE`, or `DELETE` on payments and refunds via RLS.
   - Data can only be modified through the `api_v1` SECURITY DEFINER operations.

10. **FIN-001/FIN-004 durable receipt semantics**:
    - Relies on UUIDv4 `request_id` generated by the client.
    - Stored in `private.trusted_operation_receipts`.
    - Same semantics = idempotent replay. Changed semantics = `REQUEST_ID_REUSED`.

11. **FIN-007 Preview/Commit + SHA-256 fingerprint semantics**:
    - Preview computes and returns an `impact_fingerprint`.
    - Commit requires this fingerprint. Mismatches throw `STALE_IMPACT`.

12. **BudgetItem/Installment delete guard semantics**:
    - Trigger `chk_no_financial_history_before_delete` blocks BudgetItem deletes if installments, payments, or refunds exist.
    - Trigger blocks Installment deletes if payments exist.

13. **numeric/decimal handling**:
    - Postgres DB uses `numeric(15,2)`.
    - Flutter UI (stubs) and API boundaries must parse as String/decimal-safe representations. (Note: Actual service implementation is missing in Flutter).
